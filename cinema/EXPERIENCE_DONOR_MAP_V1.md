# Trader DNA Experience Donor Map V1

Updated: 2026-09-27

This file freezes the large-loop / small-loop sourcing strategy for the 18-question public experience. It exists to prevent future drift into hand-invented effects.

## Scene 01 · Origin / Landing

Visual authority:
- user-approved EC concept composition;
- existing Trader DNA dark cinematic surface;
- approved base Species asset when delivered.

Mechanism:
- keep the existing light 3D material response already present in Detail04;
- do not install a new hero effect library.

Reason:
- the current project already has the needed pointer tilt / material response;
- the missing value is the approved Species media, not another effect.

## Scene 02 · Assessment / 18 questions

Donor checked:
- Motion Primitives `TransitionPanel` (MIT).

Useful mechanism:
- one active panel;
- enter/center/exit continuity;
- height follows content;
- spring only on spatial movement.

Production decision:
- **do not import it**.
- current question state already replaces one active panel at a time and has restrained response feedback.
- use Motion Primitives as the interaction standard, not as a dependency.

Motion class:
- M0.

## Scene 03 · Formation / Q18

Donors checked:
- Canvas UI Particle Reveal;
- existing internal `startParticleMorph()` implementation.

Production decision:
- **existing internal particle morph wins**.
- It already converts the user's 18 decision traces into the four-letter DNA and supports reduced motion / smaller mobile particle count.
- Do not replace it with Canvas UI merely to gain novelty.

Motion class:
- M2, the only M2 moment in the public assessment.

Signature contract:
- Q18 locks -> decision trace resolves -> DNA/class identity appears -> approved initial-class Species media becomes visible.

## Scene 04 · Result

Donors checked:
- Motion Primitives / Tilt (MIT);
- React Bits FlipCard interaction model.

Production decision:
- existing V47 tilt/parallax remains authority;
- RS-01 copies only the front/back state model from FlipCard;
- controls live outside the aria-hidden 3D object.

Motion class:
- M1.

## Scene 05 · Share

Donors checked:
- Codrops shared-element / FLIP layout patterns (MIT sources where used);
- existing Material 02 renderer.

Production decision:
- RS-01 visually carries the already-issued identity object to the existing share studio;
- final publish/export continues through Material 02;
- warm-white editorial artifact remains visually separate from the dark result scene.

Motion class:
- M0/M1 continuity only.

## Scene 06 · 16 Initial Classes Archive

Donor checked:
- Motion Primitives Carousel (MIT).

Useful mechanism:
- horizontal content track;
- previous/next navigation;
- item sizing independent from viewport.

Production decision:
- use **native CSS scroll-snap** first instead of importing the component.
- mount the archive only when all 16 approved thumbnails exist.
- never show empty cards, fake characters, gradients, or placeholder portraits.

Motion class:
- M0/M1.

## Dependency decision

New runtime dependencies required by EC-01: **none**.

This is intentional.

Large loop found mature mechanisms; small loop proved the current codebase already owns most of them. Only the last 10% is new:
- scene composition around approved assets;
- result flip control;
- shared-object travel into share studio;
- asset-gated class archive.

## Current blockers

Visual promotion is blocked only by approved isolated media:
1. base Species hero asset;
2. 16 initial-class result assets;
3. 16 initial-class archive thumbnails/crops;
4. optional silent 2–4s result loops.

The product runtime, scoring, 18Q flow, result/share interaction and export pipeline should not be reopened to solve those asset gaps.
